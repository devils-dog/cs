@CS2NadesBot
Бот нужен для:

- добавления новых раскидок;
- управления каталогом;
- получения Telegram user ID;
- при необходимости — администрирования.
3.2. Использовать существующий канал

@my_cs2_grenade

7. Карточка раскидки
Карточка должна быть максимально простой.
Пример:
┌──────────────────────┐
│                      │
│      [thumbnail]     │
│                      │
├──────────────────────┤
│ MONSTER              │
│ Smoke                │
└──────────────────────┘

Не использовать в интерфейсе сложные ID вроде:
OVP-T-SMK-003
или:
#map/overpass #side/t #type/smoke
Такие идентификаторы можно хранить внутри БД, но пользователю они не нужны.
8. Thumbnail
Для каждой раскидки нужен thumbnail.
Предпочтительно:
- кадр с позиции игрока;
- желательно видно место прицеливания;
- можно показывать траекторию гранаты;
- текст на изображении не обязателен.
Например:
┌──────────────────────┐
│                      │
│   игровой скриншот   │
│                      │
│       MONSTER        │
└──────────────────────┘

Thumbnail можно:
1. выбирать вручную;
2. автоматически брать первый кадр;
3. в будущем генерировать автоматически.
9. Просмотр видео
При нажатии на карточку открывать overlay/modal:
┌─────────────────────────────────┐
│                                 │
│                                 │
│             VIDEO               │
│                                 │
│                                 │
│                                 │
│      ◀                  ▶       │
│                                 │
├─────────────────────────────────┤
│ MONSTER                         │
│ Smoke • T                       │
└─────────────────────────────────┘

Видео должно запускаться максимально быстро.
Внизу:
MONSTER
Smoke · T

← Previous       Next →

Это позволит просматривать несколько раскидок подряд без возврата к сетке.
10. Хранение видео
Вариант A — простой
Видео остаются только в Telegram.
Схема:
Mini App
   ↓
карточка
   ↓
Telegram message
   ↓
видео

Плюсы:
- практически не нужно дополнительное хранилище;
- всё уже находится в Telegram;
- легко делиться видео.
Минус:
- при просмотре пользователь может покидать Mini App;
- UX хуже.
Вариант B — рекомендуемый
Использовать отдельное хранилище:
Mini App
   ↓
API
   ↓
video URL
   ↓
MinIO / S3 / CDN

Telegram при этом остаётся архивом.
Получается:
             ┌──────────────┐
             │   Telegram   │
             │    канал     │
             └──────┬───────┘
                    │
                 архив
                    │
                    ▼
┌───────────┐   ┌───────────┐
│ Mini App  │──►│ Video CDN │
└───────────┘   └───────────┘

Это предпочтительный вариант.
Видео открывается непосредственно внутри Mini App.
11. База данных
Минимальная структура:
lineups
├── id

├── target
├── title

}

12. Внутренний ID
В БД можно использовать простой slug:
overpass-t-smoke-monster

или:
overpass/t/smoke/monster

Пользователю этот ID не показывать.

Карта → фильтры → карточка

OVERPASS

      ↓
SMOKE
      ↓

      ↓
   MONSTER
      ↓
    ▶ VIDEO
      ↓
← previous      next →

Главный критерий успеха:
За несколько секунд после открытия каталога пользователь должен найти нужную раскидку и начать смотреть видео, не вводя длинный поисковый запрос и не разбираясь в структуре базы данных.

**Я бы именно этот вариант и реализовывал:** Telegram остаётся привычной точкой входа и архивом, а **Mini App становится красивым визуальным каталогом**.
